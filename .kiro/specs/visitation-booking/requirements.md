# Requirements — Visitation Booking

**Status:** Optional P1/B06.

## Acceptance criteria

EARS notation ([kiro.dev/docs/specs](https://kiro.dev/docs/specs/feature-specs/)), added 25 Jul 2026. Numbering is unchanged from the previous plain-list form, so every existing cross-reference elsewhere in this spec and in other documents still points at the same requirement.

1. THE SYSTEM SHALL allow a cemetery to expose an information-only or a bookable visitation mode.
2. WHILE a cemetery is in bookable mode THE SYSTEM SHALL enforce operating hours, capacity, blackout dates, and confirmation policy.
3. THE SYSTEM SHALL capture visitor count, contact, accessibility needs, and optional facilities on a visitation request.
4. THE SYSTEM SHALL make grave/plot navigation follow data-access policy.
5. WHEN a visitation request is submitted THE SYSTEM SHALL provide the customer confirmation, instructions, change/cancellation status, and a fallback contact.
6. THE SYSTEM SHALL show an operator only bookings for their assigned cemetery.
7. THE SYSTEM SHALL NOT create a duplicate booking from a repeated submission.
