# Requirements — Cemetery Operator Dashboard

**Source:** K34

## Acceptance criteria

EARS notation ([kiro.dev/docs/specs](https://kiro.dev/docs/specs/feature-specs/)), added 25 Jul 2026. Numbering is unchanged from the previous plain-list form, so every existing cross-reference elsewhere in this spec (`AC4`, `AC6`, `AC8` in `tasks.md`) and in other documents still points at the same requirement.

1. THE SYSTEM SHALL provide the operator with a dedicated authenticated panel.
2. THE SYSTEM SHALL show the operator only requests and orders for the operator's assigned cemeteries.
3. WHEN an operator confirms or rejects availability THE SYSTEM SHALL require a mandatory note.
4. THE SYSTEM SHALL allow an operator to update indicative package/class availability.
5. THE SYSTEM SHALL treat operator input as advisory. THE SYSTEM SHALL keep the admin as final authority for quote and payment opening.
6. WHILE the operator has not responded THE SYSTEM SHALL keep the admin manual-verification path available.
7. THE SYSTEM SHALL audit all operator decisions and data changes.
8. THE SYSTEM SHALL make dashboard adoption measurable, and THE SYSTEM SHALL NOT make the workflow dependent on that adoption.
